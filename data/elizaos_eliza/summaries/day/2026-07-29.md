# elizaos/eliza Daily Update (Jul 29, 2026)

## OVERVIEW 
Development on July 29 focused on critical production stability, specifically resolving a 100% failure rate in agent deletion jobs and addressing regressions in the CI/CD pipeline. Significant progress was made in hardening the cloud infrastructure and refining the personal assistant's audience-gating logic.

## KEY TECHNICAL DEVELOPMENTS

*   **Cloud Infrastructure & Deletion Fixes**
    *   Resolved a P0 production issue where agent deletion jobs were failing due to timestamp serialization errors ([#17260](https://github.com/elizaos/eliza/pull/17260)).
    *   Refactored deletion logic to prevent unnecessary re-writing of `deletion_started_at` timestamps during retry attempts ([#17251](https://github.com/elizaos/eliza/pull/17251)).
    *   Fixed cloud-settings token scan failures on Windows environments ([#17259](https://github.com/elizaos/eliza/pull/17259)).
*   **Personal Assistant & Runtime Security**
    *   Implemented audience-based gating for private context, normalizing room and channel types to authoritative audience classes ([#17212](https://github.com/elizaos/eliza/pull/17212)).
*   **CI/CD & Dependency Management**
    *   Repaired runtime and CI regressions, including fixes for the UI Story Gate workflow ([#17266](https://github.com/elizaos/eliza/pull/17266), [#17264](https://github.com/elizaos/eliza/pull/17264)).
    *   Executed a comprehensive dependency update sweep, including Biome, Playwright, and various cloud/benchmarking packages ([#17291](https://github.com/elizaos/eliza/pull/17291), [#17281](https://github.com/elizaos/eliza/pull/17281), [#17280](https://github.com/elizaos/eliza/pull/17280)).

*   **[#12080](https://github.com/elizaos/eliza/issues/12080) (Live Showcase Deploys):** Ongoing investigation into deployment failures. Recent audits indicate that the current API lacks durable deployment entities and concurrency guards, leading to race conditions and "unknown error" states.
*   **[#13100](https://github.com/elizaos/eliza/issues/13100) (Payout Rails):** Development is currently held due to safety gaps regarding Base-USDC enforcement and potential double-payment risks during stale-lock recovery.
*   **[#15783](https://github.com/elizaos/eliza/issues/15783) (Backup RPO):** Work continues on implementing a generation-fenced backup scheduler. Recent audits identified starvation risks in the current sweep query and the need for fleet-wide image rollouts.
*   **[#17007](https://github.com/elizaos/eliza/issues/17007) (Organization Inference Admission):** Nightly regressions show 503 errors during app monetization warm-up. The team is working to unify admission policies across chat surfaces and improve cache-warming semantics.
*   **[#17176](https://github.com/elizaos/eliza/issues/17176) (Calendar Availability):** The agent-facing source-list/select surface is now implemented, but live provider verification (Google OAuth/webhooks) remains pending.
*   **[#17179](https://github.com/elizaos/eliza/issues/17179) (Co-parent Persona):** The benchmark judge has been upgraded to use citation-gated verdicts, improving grading fidelity for the G1-G48 capability corpus.
*   **[#17249](https://github.com/elizaos/eliza/issues/17249) (Agent Deletion Failures):** Confirmed as a serialization issue where retry paths incorrectly re-wrote timestamp strings. A fix is verified on staging and backported to main.
