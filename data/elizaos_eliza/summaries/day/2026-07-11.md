# elizaos/eliza Daily Update (Jul 11, 2026)

## OVERVIEW 
Development on July 11, 2026, focused on refining cloud gateway observability, fixing token usage reporting for OpenRouter, and addressing critical infrastructure and CI issues. Significant progress was made in diagnosing latency regressions in the cloud chat gateway and improving the reliability of staging environments.

## KEY TECHNICAL DEVELOPMENTS

**OpenRouter Plugin Improvements**
* Fixed token usage reporting in `plugin-openrouter` by correctly reading cache-write tokens from `inputTokenDetails` instead of the deprecated `usage.cacheCreationInputTokens` field. ([#16136](https://github.com/elizaos/eliza/pull/16136))

## CLOSED ISSUES

**CI & Infrastructure Maintenance**

* [#16153](https://github.com/elizaos/eliza/issues/16153): Investigated latency regressions in the cloud chat gateway caused by excessive TCP rate-limit hops.

## ACTIVE ISSUES

**[#15347](https://github.com/elizaos/eliza/issues/15347) [staging][ops] Staging agents never join headscale**
* The Headscale API key 401 error was durably resolved by rotating the key on the staging CP. While the API-layer fix is verified, the issue remains open to ensure a fresh dedicated agent can successfully provision, join the mesh, and populate its `headscale_ip`.

**[#13681](https://github.com/elizaos/eliza/issues/13681) Nightly App Live E2E**
* The nightly desktop-packaged lane continues to fail. Recent analysis confirms that while specific route and screenshot tool issues were addressed, the lane has not yet achieved the required three consecutive green runs to be considered resolved.

**[#15976](https://github.com/elizaos/eliza/issues/15976) [ci] Repair Local Inference Bench**
* The benchmark continues to fail due to 404 errors when accessing manifest files. Efforts to map the catalog tiers to the new architecture slugs are ongoing, as previous attempts to fix the path cutover were incomplete.

**[#16079](https://github.com/elizaos/eliza/issues/16079) fix(observability): make chat latency telemetry truthful**
* Extensive staging benchmarks have identified that Redis-backed ingress limiters were a primary cause of latency. While recent changes have significantly reduced response-header penalties, further work is required to fully correlate per-hop latency across the gateway, auth, and provider boundaries.
